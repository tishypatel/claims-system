What is
ClaimsHub?

A modern, role-based insurance claims platform that replaces fragmented spreadsheet workflows with AI-assisted processing — designed to bring intelligence and transparency to every stage of the claims lifecycle.

Role-Based Access Real-Time Status AI Adjudication Live Analytics

A single, unified platform where claimants submit, adjusters review, AI flags anomalies, and managers track — with full audit trail and status transparency.

Part 02
AI Features

Five Layers of AI Intelligence

📷
1 · OCR Document Scanning
Vision Model

Upload a photo of any insurance document — the AI vision model reads it and auto-fills the claim form with claimant name, policy number, incident date, claim type, and amount. Confidence score included.

🧠
2 · Smart Claims Triage
Auto-run

Fires automatically in the background after every new claim. Rates complexity (simple / moderate / complex), predicts outcome, estimates processing days, and recommends handler type.

🚨
3 · Fraud Risk Detection
Auto-run

Runs automatically alongside triage on every new submission — produces a low / medium / high risk score with behavioural indicators, financial anomalies, and a step-by-step reasoning chain. Results are stored permanently on the claim.

💡
4 · AI Decision Suggestions
On demand

Adjudicator clicks "Get AI Suggestion" — the AI weighs triage results, fraud flags, adjudicator notes, and documents to return a recommendation (approve / reject / investigate further) with confidence percentage, approval likelihood, suggested payout, evidence for/against, and full reasoning chain.

💬
5 · Intelligent Chatbot
Always on

Floating widget on every page. Detects current claim from URL. Four system-prompt modes: Guest (public claim lookup by reference number), Claimant (own claims context), Adjudicator (portfolio + fraud stats), Manager (SLA and exposure overview).

Powered By
NVIDIA NIM API Large Language Model Vision Model (OCR) Live Inference

Part 04
Enterprise Readiness

Built to Scale

🗄️
Database — Already Production-Grade
Backed by Supabase PostgreSQL — a fully managed, persistent relational database. Files are stored in Supabase Storage with permanent public URLs. Chat history persists across sessions with a 30-day rolling window. No data loss on cold starts.
🔑
Authentication — Enterprise SSO
The demo uses quick-login role accounts to showcase the full experience. A production deployment would connect to an existing SSO provider or Active Directory. The authentication layer is isolated by design — RBAC logic is already in place, just needs a real identity provider.
🌐
Network & Proxy Configuration
Local development uses a built-in API proxy for simplicity. A production deployment would sit behind a reverse proxy or API gateway, with CORS policies scoped to the enterprise domain.
🔐
Secrets Management
AI service credentials are managed via environment configuration. An enterprise deployment would use a secrets vault so credentials are never committed to source control or exposed in build artefacts.
📦
Runtime & Dependency Management
Requires Node.js 18 or later. Corporate environments with internal package registries would need dependencies mirrored there. All packages are standard, widely-used libraries with no unusual constraints.
✅
What's Production-Ready Today
The frontend compiles to static files hostable anywhere. The backend is containerisable with a single config file. No platform-specific native dependencies — the production bundle is clean, portable, and deployment-agnostic.
Part 04
Deployment Roadmap

Path to Production

✓
Persistent Database & Storage Done

Supabase PostgreSQL is already in production — persistent across cold starts, 5-table relational schema, file storage for documents with permanent public URLs. No migration needed.

2
Connect Identity Provider Week 1–2

Wire an enterprise SSO or directory service into the existing authentication layer. Role-based access control is fully built — it just needs a real identity provider in place of demo accounts.

3
Containerise & Deploy Week 2

Package the backend into a container and configure a reverse proxy to serve the frontend and route API traffic. Mirror dependencies to the internal package registry if required.

4
Secrets & CI/CD Pipeline Week 3

Move AI service credentials to an enterprise secrets vault. Configure a CI/CD pipeline for automated build, test, and deploy on every merge to main.
